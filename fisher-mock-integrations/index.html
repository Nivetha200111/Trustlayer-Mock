Fisher Mock Integrations

Stand-in TrustLayer (COI verification) and eCMS (subcontract) APIs for the Fisher Industries ServiceNow demo.

Checking service health…
These are demo mocks with deterministic data. They are not the real TrustLayer or eCMS systems.

Authentication

Every endpoint except /api/health needs the header x-api-key. Every response is JSON, and errors use 4xx codes (401 wrong key, 405 wrong method, 400 bad input).

Endpoints

GET/api/health

Liveness check. No key needed.

POST/api/trustlayer/coi-check

Body: vendor_name (required), project_code, reference. Returns the status, the Fisher requirements, the certificate on file, and any gaps.

curl -X POST /api/trustlayer/coi-check \
  -H "Content-Type: application/json" -H "x-api-key: $MOCK_API_KEY" \
  -d '{"vendor_name":"Red Mesa Equipment Services LLC","project_code":"85117","reference":"CMR0001001"}'
POST/api/ecms/subcontracts

Body: contract_number, vendor_name, project_code, amount (all required), plus optional cost_code, start_date, end_date. Idempotent: the same contract number always gets the same subcontract_no.

curl -X POST /api/ecms/subcontracts \
  -H "Content-Type: application/json" -H "x-api-key: $MOCK_API_KEY" \
  -d '{"contract_number":"CNT0010042","vendor_name":"Red Mesa Equipment Services LLC","project_code":"85117","amount":184500}'
